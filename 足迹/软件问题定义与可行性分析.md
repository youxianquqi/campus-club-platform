### 软件问题定义：基于冷启动的社团招新管理系统

#### 1. 项目背景
高校社团招新目前多采用线下摊位、线上群聊或简单表单收集的方式，存在以下问题：
- 新生面对众多社团信息过载，难以快速找到匹配自身兴趣的社团。
- 新成立社团缺乏历史数据，难以获得曝光机会。
- 招新流程分散，报名与审核依赖人工统计，效率低且易出错。
- 学生与社团管理者之间缺少统一的线上协作平台。

#### 2. 项目目标
开发一个面向高校的社团招新管理系统，实现以下目标：
- **简化登录**：学生直接使用学号和身份证后六位登录，无需注册。
- **兴趣匹配**：基于预设的兴趣标签，为新生提供个性化的社团推荐，解决冷启动问题。
- **高效报名**：支持学生在线填写报名表并提交，社团管理员可在线审核。
- **流程闭环**：形成从推荐、报名到审核、结果反馈的完整招新流程。

#### 3. 用户角色
系统涉及两类用户：
- **学生**：系统的核心使用者，浏览推荐、报名社团、查看审核结果。
- **社团管理员**：管理本社团信息，审核报名申请。

（系统管理员角色仅在后台维护数据，不直接参与业务流程，可暂不纳入问题定义）

#### 4. 功能范围
系统需提供以下核心功能：

| 功能模块 | 功能描述 |
|----------|----------|
| 登录模块 | 学生输入学号、身份证后六位完成身份验证，首次登录强制选择兴趣标签。 |
| 标签管理 | 系统预设兴趣标签库（如“编程”“摄影”等），学生只能从中勾选，不可自定义。 |
| 社团管理 | 社团管理员维护社团基本信息（名称、简介、标签），系统管理员可代建。 |
| 推荐模块 | 基于学生选择的标签，采用Jaccard相似度计算与社团标签的匹配度，按匹配度降序展示推荐列表（不显示推荐理由）。若学生未选标签，则按报名人数展示热门社团。 |
| 报名模块 | 学生填写自我介绍、联系电话，提交社团报名；系统记录报名状态（待审核）。 |
| 审核模块 | 社团管理员查看本社团报名记录，审核通过或拒绝（拒绝需填写理由）。 |
| 个人中心 | 学生查看自己的报名记录及状态，若被拒绝可查看理由。 |

#### 5. 非功能需求
- **易用性**：界面简洁，操作步骤少，符合学生使用习惯。
- **性能**：支持至少500人同时在线，页面加载时间不超过3秒。
- **安全性**：密码（身份证后六位）加密存储，接口需验证登录状态。
- **可维护性**：采用前后端分离架构，代码模块清晰，便于后续扩展。

#### 6. 约束条件
- 开发语言：Java + Spring Boot（后端），Vue.js（前端）。
- 数据库：MySQL。
- 推荐算法：仅基于标签的集合相似度，不引入复杂机器学习模型。
- 登录信息：学生学号与身份证后六位需提前导入系统（由学校提供基础数据）。

#### 7. 预期成果
- 一个可运行的社团招新管理系统，包含学生端和管理员端。
- 系统能够根据学生兴趣标签进行社团推荐，并支持在线报名与审核。
- 配套毕业论文，阐述系统分析、设计、实现与测试过程。

### 可行性研究报告

#### 1. 引言
本报告针对“基于冷启动的社团招新管理系统”项目，从技术、经济、操作、法律等维度进行可行性分析，以确定项目是否具备实施条件。

#### 2. 技术可行性
**2.1 开发技术成熟度**  
系统采用主流技术栈：  
- 后端：Java + Spring Boot，已广泛应用于企业级Web开发，社区活跃，文档丰富。  
- 前端：Vue.js + Element Plus，轻量高效，组件库丰富，适合快速构建管理界面。  
- 数据库：MySQL，稳定可靠，支持事务与复杂查询，完全满足数据存储需求。  
- 推荐算法：仅需实现基于标签集合的Jaccard相似度计算，无需机器学习框架，实现简单。

**2.2 团队技术能力**  
开发成员为软件工程专业毕业生，已完成Java、数据库、Web开发等相关课程，具备Spring Boot和Vue的基础知识。通过查阅文档和利用AI辅助，可在规定时间内掌握所需技能。

**2.3 软硬件环境要求**  
- 开发环境：普通PC（Windows/macOS），安装JDK、Node.js、MySQL、IntelliJ IDEA/VSCode即可。  
- 运行环境：可部署于校内服务器或云主机（如阿里云学生优惠实例），配置要求低（2核4GB内存即可）。

**结论**：技术方案成熟，难度适中，现有资源足以支撑项目开发。

#### 3. 经济可行性
**3.1 开发成本**  
- 人员成本：项目由学生独立完成，无额外人力支出。  
- 软件成本：开发工具均采用免费版（IntelliJ Community、VSCode、MySQL Community），无需购买商业许可证。  
- 服务器成本：初期可部署于本地，如需上线可申请学校服务器或购买低价云服务器（学生优惠约100元/年），成本极低。

**3.2 维护成本**  
系统上线后，仅需少量维护（数据备份、异常处理），可由学校信息中心或社团联合会兼职管理，无持续资金投入。

**3.3 预期效益**  
- 提高招新效率，减少人工统计工作量。  
- 增强新生参与度，提升社团招新质量。  
- 可作为毕业设计成果，为求职增加竞争力。

**结论**：项目几乎零成本投入，且能带来实际效益，经济上完全可行。

#### 4. 操作可行性
**4.1 用户接受度**  
- 学生：登录方式简单（学号+身份证后六位），无需记忆额外密码；界面直观，操作流程短，易于上手。  
- 社团管理员：可通过后台快速审核报名，减少手动整理表单的繁琐。  
- 系统管理员：只需预先导入学生基础数据和社团信息，后续维护简单。

**4.2 组织管理可行性**  
项目旨在解决高校招新实际问题，符合社团联合会和学生工作部门的需求。可与学校相关部门沟通获取基础数据支持，并争取试点运行。

**4.3 流程适应性**  
系统流程与现行招新流程高度契合（推荐→报名→审核），无需改变用户习惯，仅将线下或分散流程线上化，操作阻力小。

**结论**：用户接受度高，组织配合可行，操作上具备推广基础。

#### 5. 法律可行性
**5.1 数据隐私**  
系统仅采集学生学号、身份证后六位（用于登录验证）、姓名、兴趣标签、联系方式等必要信息。身份证后六位加密存储，不保存完整身份证号，符合个人信息保护要求。  
**5.2 软件版权**  
使用开源技术栈（Spring Boot、Vue、MySQL等）均遵循相应开源协议（如Apache 2.0、MIT），无版权纠纷。  
**5.3 合规性**  
项目为校园内部管理工具，不涉及商业运营，不违反法律法规。

**结论**：法律风险可控，符合数据安全与知识产权规定。
